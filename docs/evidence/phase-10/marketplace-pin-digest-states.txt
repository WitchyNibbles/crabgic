--------------------------------------------------------------------------------
0. THE RESIDUAL, IN ONE PARAGRAPH
--------------------------------------------------------------------------------
`packages/plugin/.claude-plugin/marketplace.json`'s entry couples `version`,
`commit` and `digest`. Only `digest` is kept fresh per push —
`packages/plugin/src/marketplace-schema.test.ts`'s freshness assertion forces
any PR touching a packaged plugin file to rewrite it in the same commit —
while `version` and `commit` move only at a release cut. So between cuts the
entry describes HEAD's plugin content while naming the PREVIOUS release's
commit and version.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------
Each commit's own `packages/plugin` exported with `git archive` into a temp dir
OUTSIDE the repository, then classified by THE PRODUCTION CLASSIFIER

--------------------------------------------------------------------------------

intervening diff is confined to `packages/plugin/.claude-plugin/`. Measured, the

returned `mismatched`, not tolerated. It did not run, because `e2e/release` is
not a `vitest.config.ts` project and its sole production caller is the release
gate summary.

⇒ "the tolerance already makes this a non-problem" is FALSE. It is a non-problem
for a different, measured reason: §3.

8. THE TRANSCRIBED DIGEST IS BOUND TO ITS SOURCE
--------------------------------------------------------------------------------
`scripts/check-marketplace-pin-digest.mjs` reimplements
`packages/plugin/src/content-digest.ts`, because `meta-checks` runs on `npm ci`
and never builds, so `@crabgic/plugin` (which resolves through
`packages/plugin/dist/`) is not importable there. `content-digest.ts:21-27` is
itself pinned by a merged citation and must not be edited, which is the other
half of why the behaviour lives in a new file.

Three witnesses bind the copy to the original, all asserted in the suite:

  1. `computeContentDigest(PLUGIN_ROOT)` === `@crabgic/plugin`'s own, on the real
     plugin tree;
  2. `listPackagedFiles(PLUGIN_ROOT)` equals the TypeScript module's list file
     for file — because two implementations can agree perfectly by both walking
     nothing;
  3. that digest equals the one the COMMITTED entry records — because two
     implementations agreeing proves they are the same function, not that either
     is right.

The packaged set at `cb450e3` is 18 files (`.mcp.json`, 5 `agents/`, 4 `hooks/`,
6 `skills/`, 2 `statusline/`). The suite asserts a floor of 10 rather than
pinning 18, so adding a plugin file is not a spurious failure; the file-for-file
equality above is what actually holds the two walks together.

`GIT_*` variables are scrubbed from every git invocation, for the same reason
`scripts/check-repo-hygiene.mjs` scrubs them.

9b. ⚠️ THE REPO'S OWN GUARD REDDENED THIS SCRIPT'S FIRST DRAFT — and was right
--------------------------------------------------------------------------------
Recorded because it is the kind of thing that is otherwise silently fixed and
lost. The first draft routed all three git calls through one
`git(repoRoot, args, options)` helper. The full-suite gate went RED:

    FAIL |@crabgic/testkit| src/git-spawn-hygiene.test.ts
         > every file that spawns a MUTATING git command references a
           sanctioned environment scrub
    AssertionError: expected [ Array(1) ] to deeply equal []
    +   "scripts/check-marketplace-pin-digest.mjs",
    Test Files  1 failed | 651 passed (652)
         Tests  1 failed | 6813 passed (6814)

That guard classifies a spawn by the LITERAL first element of its argv array
(`git-spawn-hygiene.test.ts:51-52`, and its own comment explains why a leading
dash must not be capturable). A generic helper passing a variable `args` is
unclassifiable, so it is assumed MUTATING and must name a sanctioned scrub —
`runFixtureGit`/`gitFixtureEnv`/`GIT_LOCATION_ENV_VARS` — none of which a
build-free `meta-checks` script can import.

The draft DID scrub `GIT_*`, with its own local `scrubbedGitEnv`. The guard
could not see that, and its refusal is presence-not-proof by design.

FIXED BY WRITING EACH CALL SITE WITH ITS LITERAL SUBCOMMAND, not by adding the
magic identifier to a comment. `rev-parse`, `merge-base` and `archive` are all
in the guard's read-only set, so the module's "read-only throughout" claim is
now checked by a machine instead of asserted in prose — which is strictly better
than what the helper had. The script carries a DO-NOT-REFACTOR note at the seam
saying so, because collapsing three literal call sites into one helper is
exactly the tidy-up a future reader would reach for.

    after the fix:
      packages/testkit/src/git-spawn-hygiene.test.ts   4 passed (4)
      scripts/check-marketplace-pin-digest.test.mjs   20 passed (20)

9c. ⚠️ AND THEN CI CAUGHT WHAT A GREEN LOCAL GATE COULD NOT — the shallow clone
--------------------------------------------------------------------------------
The full local gate was GREEN — 652 files / 6814 tests, EXIT=0 — and the same
suite failed on BOTH arches in CI. Recorded because it is the sharpest instance
in this pass of a rule this repository already knows: a green run somewhere is
not a green run in the channel that matters.

    PR #131, run 31181816965
      unit-test+coverage (ubuntu-latest)     fail   4m16s
      unit-test+coverage (ubuntu-24.04-arm)  fail    4m8s
      every other job on both arches         pass

    from the job log:
      fatal: not a valid object name: b5a609c
      fatal: not a valid object name: cb450e3
      × resolves a real commit and refuses a 40-hex string that is not an object
      × reports ancestry in the direction it claims, and refuses the reverse
      × classifies THIS worktree, and it is legal
      × prints the ahead-of-pin drift rather than passing silently
      × renders a FAIL to stderr with a non-zero exit
      × reproduces all five measured commits, using the real classifier
      × removes its scratch directory on cleanup
      AssertionError: expected [ 'at-release', 'ahead-of-pin' ] to include 'unresolvable-pin'

CAUSE: `actions/checkout`'s default is a DEPTH-1 SHALLOW CLONE. The `meta-checks`
job already sets `fetch-depth: 0` (for the criteria-baseline re-derivation), which
is why `npm run check:marketplace-pin` was green there — but the `test` job did
not, so every historical commit this suite classifies was absent. A developer's
clone has the history; the runner's did not. The local gate could not have caught
this, and no amount of re-running it would have.

REMEDY, and the shape of it matters:

  1. `fetch-depth: 0` on the `test` job's checkout, with the reason written at
     the setting rather than in a commit message.
  2. A FIRST-CLASS ASSERTION that the history is present, listing the missing
     revisions and naming `fetch-depth: 0` in its failure message — so a future
     revert fails with ONE actionable line instead of seven that point
     elsewhere. The corpus list is a single `CORPUS_COMMITS` constant shared
     with the historical-corpus test, so the guard and the thing it guards
     cannot drift.

  ⛔ REFUSED: skipping those assertions when history is absent. That is the
  defect class `ci.yml`'s own bubblewrap guard was rewritten to avoid — a suite
  that early-returns on a missing prerequisite reports a green tick having
  asserted nothing.

    after the fix, locally:  21 passed (21)   (20 before, +1 for the guard)
