2.4 NEW ENGINE FACT — `maxTurns` in an agent's frontmatter (byte-sourced from
    the pinned 2.1.218 binary; NOT probe-verified, and NOT yet in
    `docs/engine-baseline.md` — see §6, "Owed")

  Known frontmatter key, listed beside the keys this repo already writes:
    "keywords","compatibility","tools","disallowedTools","color",
    "permissionMode","maxTurns","initialPrompt","memory","background",
    "isolation","observer",…

  Schema, and it is exactly the constraint the new manifest rule enforces:
    maxTurns:b.number().int().positive().optional()

  Validated for PLUGIN agent files specifically, and dropped when invalid:
    Plugin agent file ${e} has invalid maxTurns '${$}'. Must be a positive integer.
  (the warning is followed by the value being omitted from the assembled agent,
   which silently restores the default below — an invalid bound looks installed
   and is not.)

  Built-in default for an agent that declares none:
    tools:["*"],maxTurns:200,model:"inherit"

  And the loop's own terminator, which is what a declared bound buys:
    yield Ka({type:"max_turns_reached",maxTurns:c,turnCount:Ln},f)

  Together these corroborate `docs/verification-playbook.md` §BOUNDING A
  SUBAGENT-SPAWNING TEST from the engine side: the subagent loop carries its own
  budget, defaulting to 200, and no parent-side flag reaches it.

6. RESIDUALS AND OWED WORK — stated, not softened
--------------------------------------------------------------------------------

 * UNVERIFIED against a live engine. Everything in §5 is a precondition. The
   owner action that verifies it: dispatch `engine-live` once, in a
   low-utilization window, after confirming the `CLAUDE_CODE_OAUTH_TOKEN`
   repository secret exists. A hot-window dispatch is a cheap red (the canary
   aborts at utilization >= 0.85); the expensive red was the late-file ENOENT,
   which this batch removes.
 * Four of the five manager subagents (eo-reviewer, eo-roaster, eo-architect,
   eo-planner) still run at the built-in 200-turn default. Deliberate: the
   overspend was measured for eo-explore only, and a bound that bites mid-review
   truncates a reviewer's findings. Pinned by an assertion (probe F).
 * OWED — `docs/engine-baseline.md` carries no section for §2.4's agent
   frontmatter facts, so `agents/eo-explore.md`'s new `maxTurns` cites this
   transcript rather than the baseline the ground rule names. This batch's file
   scope excludes that document; the fact needs landing there as a carry-forward,
   the way §12's `enabledPlugins` fact was. Until then, treat §2.4 as
   binary-sourced and not probe-verified — the same evidentiary class the
   baseline's own §16/§17 declare for themselves.
 * The `engine-live` job still runs both lanes together, so a plugin-lane
   failure still costs whatever the engine-claude lane spent before it. `--bail`
   bounds that; splitting the plugin lane into its own job would remove it, and
   is not attempted here.
