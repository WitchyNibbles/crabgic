--------------------------------------------------------------------------------
5. WHAT IS AND IS NOT CLAIMED
--------------------------------------------------------------------------------
CLAIMED: the exemption is presence-only over whole-file text; exactly one file in
the tree matches it in prose alone; that file spawns a mutating git command; and
a mutating spawn added to it is not flagged (probe B), while removing the prose
token flags the file as it already stands (probe D).

NOT CLAIMED: that any current spawn is unsafe. §2 says the opposite, measured
against the fixture's own construction.

NOT CLAIMED: that the census's comment-stripping is exact. It is a regex pass; it
produced one candidate and the candidate was confirmed by execution.

NOT CLAIMED: that presence-not-proof is the wrong trade. `git-spawn-hygiene`'s
own header calls it "presence, not proof — enough to make the omission loud", and
the playbook rules it "a deliberate trade (cheap, hard to bypass by accident)".
The gap is narrower than that trade: there is no way to SAY "deliberately
unscrubbed, and here is why", so the only way to say it is the same string that
turns the rule off.

NO PRODUCTION CODE WAS CHANGED BY THIS PASS. Filing is the deliverable; the fix
is separate work with its own TDD trail.
