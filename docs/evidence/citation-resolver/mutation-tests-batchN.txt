C. WHAT THESE PROBES DO NOT COVER — stated, not implied
===============================================================================

- ci-run citations' quoted job-log lines are NOT checked by any CI lane. The
  normalization (ANSI strip + timestamp + one-space, with the two-space form
  twelve merged records use grandfathered) is implemented and unit-tested in
  scripts/citation-content/job-log.mjs and driven by --report --job-logs <dir>
  over logs a pass has already downloaded. It needs the network and a token;
  meta-checks has neither. UNVERIFIED against a live job log in this pass.
- Rules 3 (group consecutiveness) and 4 (repeat text) are reported, never
  blocking, and their report output is not mutation-tested beyond the unit
  battery's repeat-text control.
- `--fix` is covered by its refusal guard, by the full pipeline
  (parseQuotedAssertion -> resolveRecord -> buildMarkerEdits -> applyMarkerRewrites)
  over a fixture, and by same-ref selection through citationOf. The one thing NOT
  covered is the final writeFileSync over a real git-backed record: driving that
  needs a fixture repository, and see section D for why this pass will not ship one.
- The prose lane blocks on past-EOF and on a deleted repo-rooted path, and stays
  silent on bare basenames and package-relative fragments, which cannot be
  resolved without guessing. Those 33 remain reported-only.
- A cross-file quote written with a bare filename and NO line number resolves
  against the citation's own ref file, because letting a bare filename switch
  files re-pointed seven phase-00 fragments at a deleted path. Such a quote is
  reported ABSENT/MOVED rather than checked against the file it names.

===============================================================================
D. INCIDENT — this pass damaged the repository, and the first disclosure of it
   was itself incomplete. Both facts, in full.
===============================================================================

WHAT HAPPENED. An earlier version of this suite tested --fix by building a real
git fixture repository: mkdtemp, then git init / config / add / commit /
update-ref with { cwd: tempDir }. Under a fully parallel `npm test` those
commands did not act on the temp directory. They acted on the REAL worktree.

MEASURED DAMAGE, all four parts:
  1. two junk commits ('base', "this branch's own draft") on
     closeout/batch-n-citations, whose tree was the fixture, not the repo;
  2. refs/remotes/origin/main clobbered to point at the fixture commit;
  3. core.bare = true written into the SHARED .git/config, after which
     `git status` in the main checkout failed with
     'fatal: this operation must be run in a work tree';
  4. [user] name/email in that same config overwritten with the fixture identity
     fixture / fixture@example.invalid.

WHAT THE FIRST DISCLOSURE GOT WRONG. It reported the incident as fully cleaned.
It was not. Parts 1 and 2 were repaired; parts 3 and 4 were NOT, and were found
still live in review — `git status` was still failing in the main checkout at
that point. The cause of the miss is worth more than the miss: the check made was
'are the refs and files right?', and .git/config is neither a ref nor a file in
the tree. All four symptoms are enumerated verbatim in
packages/testkit/src/git-env.ts:20-29, written after the SAME class of incident on
2026-08-01 — the repair was scoped by what had been noticed rather than by the
existing account of what this failure does. A disclosure that says 'fully cleaned'
when it is not is worse than the incident: it retires the question.

REPAIR (verified): core.bare=false, committer identity restored, refs restored
from origin, junk commits reset, worktree clean, `git status` healthy.

PREVENTION, not just detection. git-env.ts is an OPT-IN overlay, so it protects
only the fixtures that remember it — and this class has now fired twice. The
structural fix in this PR is vitest.setup.mjs, wired into the root config, which
deletes every GIT_* variable from EVERY test process before any test file loads.
git resolves GIT_DIR ahead of cwd, and the pre-push hook exports one aimed at the
repository being pushed, which is why { cwd: tempDir } was decoration. A test
asserts the scrub is still wired, so it cannot be removed in silence.
