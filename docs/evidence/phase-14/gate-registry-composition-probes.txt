TWO CHANGES, and the reasoning for each:

1. **T4 is now sequential by DAG dependency.** Its subject is conflict detection
   against the ADVANCING integration tip, not the scheduler's concurrency.
   Dispatching both units in one round adds a variable that has nothing to do with
   the claim — two concurrent `git worktree add`s racing the control clone's shared
   `.git/config` lock, which is the most plausible route to a pre-pipeline `failed`.
   `dependsOn` removes it. The conflict is unaffected: every attempt worktree is
   cut at the frozen base regardless of round, so B's candidate still diverges from
   A's integrated tip.
2. **The pipeline's own reason is asserted FIRST**, so the next failure of this
   test reports WHY rather than only a state mismatch.

HONEST RESIDUAL: the root cause was not confirmed, only removed from this test's
path. If a pre-pipeline `failed` recurs anywhere, the drive-error assertion added
