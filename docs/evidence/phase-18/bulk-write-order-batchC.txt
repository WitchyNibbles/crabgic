0. WHAT WAS OPEN, AND WHAT THIS CLOSES
--------------------------------------------------------------------------------

roadmap/18 §Exit criteria 10 second clause: "per-issue write order preserved."
PR #84 closed it for SINGLE-issue writes and deliberately left `bulk:<keys>`
unserialized, pinning that residual as an assertion in
packages/connectors-jira/src/resource-client/canonical-target.test.ts.

The gateway primitive this needs (`WriteSerializer.runExclusiveMulti` and
`GatewayHttpRequest.serializationResources`) landed on this branch's first
commit. It was DEAD CODE for Jira until this batch: both apply clients called
`writeSerializationTarget(plan.canonicalTarget)`, and that function passed a
`bulk:` target straight through.

Fix: `writeSerializationTarget` returns `string | readonly string[]`, and maps
`bulk:K1,K2` onto the sorted, deduped set ["issue:K1","issue:K2"]. Neither
apply client's call site changed — the widening is entirely inside
canonical-target.ts, so Cloud and Data Center inherit it together.

PR #125's body originally carried a paragraph headed "Honest limit on this

that the job log therefore prints ONLY the repo-wide summary, with no per-file

The per-file lines are present in both logs. They are ANSI-colour-coded, so:

  $ grep -c "write-order.integration.test.ts (" joblog-pr125.txt

shape the verification playbook names for mis-scoped pathspecs and
notation-blind greps. Strip the escapes first and the lines are all there:

  $ sed -E 's/\x1b\[[0-9;]*m//g' joblog-pr125.txt | grep '…test.ts ([0-9]* tests)'

body was corrected. This section exists so the finding lives in the repo rather
than in a review thread: the correct method wave-wide is "strip ANSI escapes,
THEN grep", and a per-push proof must not be downgraded on the strength of a
grep that returned nothing.
