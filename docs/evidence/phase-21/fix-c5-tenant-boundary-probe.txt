It is NOT true that the enforcement had no per-push net, and nothing in this file should be
read that way. `checkGrafanaConnectionDoctor`'s org-allowlist check IS exercised on every push,

Those three are in the default fan-out and were green-under-deletion nowhere.

What the tautology actually cost is narrower and still real:

  1. THE STANDING BLOCKING GATE. `registry.list("security")` reported tenant-boundary coverage
     that could not fail. That is the guarantee phase 21 criterion 5 is about — fixtures
     "graduated from one-off phase-exit checks to standing, continuously-run gates" — and it
     was absent. A blocking gate that cannot fail is worse than an absent one, because it
     reads as coverage.
  2. THE `e2e/matrix` DEPTH. `e2e/matrix/connector/src/connector-security/tenant-boundary.test.ts`
     exists but has no per-push net of its own: `package.json`'s `workspaces` is `["packages/*"]`,
     the root `vitest.config.ts` projects are `packages/*` plus `e2e/report`, and the only
     workflow that names `e2e/matrix` is `release-e2e.yml`. Verified in this tree, not assumed.

So the honest statement is: the enforcement was tested; the GATE was not. This addendum exists
because an inflated residual is its own kind of dishonesty, and this file will outlive the
argument that produced it.
