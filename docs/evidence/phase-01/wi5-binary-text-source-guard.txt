== 1. THE REPO-WIDE SCAN — it was never one file ==

  git classifies a file as binary when a NUL falls in its first 8000 bytes.
  `git diff --numstat <empty-tree>` diffs that tree against the WORKING tree
  and renders a binary addition as `-<TAB>-<TAB>path`, so this is git's own
  classifier rather than a reimplementation of it.

$ git diff --numstat $(git hash-object -t tree /dev/null) \
    | awk -F'\t' '$1=="-"&&$2=="-"{print $3}' | grep -v '^assets/'
  packages/gateway/src/transport/write-serializer.ts
  packages/learning/src/eval/eval-pair.ts
  packages/renderer/src/unicode-defense.test.ts
  packages/renderer/src/wiki-markup.ts

  FOUR files, seven raw NUL bytes, all the same typo class:

    write-serializer.ts:15   `${key.tenant}<0x00>${key.resource}`
    eval-pair.ts:44          [...].join("<0x00>")
    unicode-defense.test.ts:103   stageInput("abc<0x00>def")
    wiki-markup.ts:20-21     "<0x00>WIKI_STRONG_OPEN<0x00>"  (x2 lines, 4 bytes)

  The 22 entries filtered out by `grep -v '^assets/'` are the brand PNGs and
  one committed `__pycache__/*.pyc` — genuinely binary, correctly binary, and
  out of scope for the guard below by extension rather than by allowlist.

     ^ NO output and a non-zero exit. `-I` does not warn; it silently drops

       opened. This is the same failure shape as a mis-scoped pathspec: a
       SMALLER answer with no error.

  And `git diff` renders all four as "Binary files ... differ", which is why
  eval-pair.ts's 97 lines were unreviewable in the PR that introduced them
  (#115, squash 2c0562d) and remain unreviewable on GitHub.

  Nothing per-push saw any of it. tsc, eslint, prettier and vitest were green
  the entire time — correctly, because the files are valid TypeScript and the
  runtime values are exactly what was intended. The program was never wrong.
  The tooling that verifies the program was.

  Scoped by EXTENSION, not by path. A git pathspec would have been the
  natural way to write "under packages/*/src" and is the exact shape that
  returns a smaller answer silently — a wildmatch `*` does not cross a slash.
  The extension allowlist also needs no growable exception list, because the
  repo's real binary assets carry none of those extensions. `.gitattributes`
  `diff` stays available as git's own documented escape hatch, and being a
  committed file it is visible rather than private to the script.

  legitimately-binary-asset control reddens. That control is what separates
  "this check has a scope" from "this check flags every PNG in assets/".

  PINNED RESIDUAL, asserted in the suite rather than described here: a NUL
  beyond git's 8000-byte sniff window is NOT detected. That is deliberate —
  past the window git still diffs and greps the file as text, so the
  instruments keep working and there is nothing to report. If git ever widens
  the window, that test reddens, which is the correct notification.

== 6. THE REVERSE PROBE — and what it found ==

  Equal test counts prove the fix changed nothing. They do not prove the
  suite would have NOTICED had it changed something. So each separator was
  rewritten to a colliding one and the suites re-run:

    C2  eval-pair       .join("\0")  ->  .join("|")                74 files / 785 tests GREEN
    D2  wiki-markup     "\0WIKI_STRONG_OPEN\0" -> "@@...@@"        74 files / 785 tests GREEN
    E2  write-serializer `${tenant}\0${resource}` -> `${tenant}:${resource}`
                                                                   74 files / 785 tests GREEN

  Every mutation was verified to have APPLIED before the run (occurrence
  count asserted non-zero) — a first attempt at these three used a perl
  substitution whose backslash escaping did not match, and reported three
  green runs of entirely UNMUTATED code. Caught by checking the substitution
  count rather than the exit status, which is the only thing that separates
  that transcript from this one.

  FINDING: none of the three separators is pinned by any test in the
  repository. The "value-preserving" claim in section 5 therefore could not
  have been checked by the suite at all; it rests on the digest computation
  above and on `"\0"` being U+0000 by language definition.

  One of the three is now pinned (323d7fb, learning): two case sets that
  differ only in where the field boundary falls must not digest identically.
  Under mutation C2 it is the ONE test in the repository that reddens:

    baseline                        Test Files 24 passed / Tests 238 passed
    C3  separator \0 -> "|"         Test Files 1 failed | 23 passed / Tests 1 failed | 237 passed
        x the per-case field separator is unambiguous — moving a field boundary changes the digest
        AssertionError: expected '35747840548fda4209c810d690cd113100d51...' not to be '35747840548fda4209c810d690cd113100d51...'
    restored                        Test Files 24 passed / Tests 238 passed

  gateway's and renderer's separators are LEFT UNPINNED, stated rather than
  quietly skipped: pinning them is a different piece of work from this typo
  fix, and claiming otherwise would oversell the remedy.
